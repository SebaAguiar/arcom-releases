# Publishing a Release

Workflow for publishing a new Arcon desktop build to this repository so
the Tauri auto-updater picks it up.

## Prerequisites

- Build succeeds on your machine (`pnpm build:launcher` produces
  `apps/arcon-launcher/src-tauri/target/release/bundle/`).
- Signing keys are present (see "Signing" below). Without a signature
  Tauri refuses to update.
- `gh` CLI authenticated (`gh auth status`).

## Steps

### 1. Build all bundles

```bash
cd arpos-v2
pnpm build:launcher
```

Artifacts land in:

```
apps/arcon-launcher/src-tauri/target/release/bundle/
├── deb/       Arcon_<version>_amd64.deb
├── rpm/       Arcon-<version>-1.x86_64.rpm
├── appimage/  Arcon_<version>_amd64.AppImage
```

> Linux AppImage bundling currently fails with the bundled `linuxdeploy`
> `strip` (does not understand `.relr.dyn` from GCC 13+). Publish the
> `.deb`/`.rpm` and fix the AppImage toolchain separately.

### 2. Sign every asset

Tauri requires an Ed25519 signature per artifact.

```bash
cd apps/arcon-launcher/src-tauri
for f in target/release/bundle/{deb,rpm,appimage}/*.{deb,rpm,AppImage}; do
  npx tauri signer sign -k ~/.tauri/arcon.key -w "${f}.sig" "$f"
done
```

> The private key `~/.tauri/arcon.key` is stored out-of-band. Regenerated
> on 31-jul with the passphrase documented in `docs/context/UPDATES.md`.

### 3. Create the GitHub release

From the **arcon-releases** repo:

```bash
cd ../arcon-releases
gh release create v1.0.0 \
  ../arpos-v2/apps/arcon-launcher/src-tauri/target/release/bundle/deb/*.deb \
  ../arpos-v2/apps/arcon-launcher/src-tauri/target/release/bundle/deb/*.deb.sig \
  ../arpos-v2/apps/arcon-launcher/src-tauri/target/release/bundle/rpm/*.rpm \
  ../arpos-v2/apps/arcon-launcher/src-tauri/target/release/bundle/rpm/*.rpm.sig \
  --notes "Release notes for v1.0.0"
```

### 4. Verify the updater endpoint

```bash
curl -s https://api.github.com/repos/SebaAguiar/arcon-releases/releases/latest \
  | jq '.tag_name, .assets[].name'
```

The app's updater (see `updater.rs` in arpos-v2) fetches this endpoint;
`releases/latest` returns the most recent release automatically.

## Naming convention

- Bundle: `Arcon_<version>_<arch>.<ext>` (generated by Tauri)
- Signature: identical name plus `.sig` suffix, next to the asset

The updater derives `.sig` URLs by convention — keep the `.sig` file
name identical to the asset name.

## Signing keys

- Private key: `~/.tauri/arcon.key` (never commit)
- Public key: embedded in `tauri.conf.json` (`bundle.createUpdaterArtifacts`
  / pubkey field). To see the pubkey:

```bash
npx tauri signer info --key ~/.tauri/arcon.key
```

## Rollback

GitHub Releases keeps every tag. Point the app to an older release by
re-targeting `releases/latest` (delete/re-tag) or by setting
`updater.endpoints` in `tauri.conf.json` to a pinned tag:
`.../releases/download/v1.0.0/latest.json`.

## Checklist

- [ ] `pnpm build:launcher` succeeded
- [ ] Every asset signed (`.sig` next to it)
- [ ] Release created with all bundles + signatures
- [ ] `curl` on `/releases/latest` returns new tag + assets
- [ ] Version bumped in arpos-v2 (`tauri.conf.json`, `Cargo.toml`,
      `package.json` files)
